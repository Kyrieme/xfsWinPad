v0.13.4（2026-09-21）

  • 新增「语句悬停提示」：把鼠标停在 .pln 里的语句名上 （例如 FORCE_V_PPMU），会弹出气泡直接显示手册里的原始函数语法 和原始说明，格式就是手册原文的 签名);//说明，例如 FORCE_V_PPMU(pin_name, f_volt, v_range, I_range, I_clamp, wait_time);//This statement sets the Per-pin PMU in voltage force mode…。 共覆盖 309 条语句：256 条语法与说明都有，51 条只有说明 （手册里本来就没给语法行），2 条语法里带注释、按"不是语法"处理只显示说明。 说明文字是从语言手册里逐条抽取的（页码、页眉这类版面残留已剔除）， 不是手写摘要 —— 所以你看到的就是手册原话
  • 顺手修掉一个"看得见但一直没人注意"的显示缺陷：长文案在气泡里会 从词中间被裁掉 —— 例如某条第一行结尾变成 …sets the Per-pin PMU in voltag，尾部字母直接消失，而且系统不报任何错。 这类文案中位数 160 字符、最长 1234 字符，超过九成都会触发。 现在改成按像素自己折行（用气泡自己的字体量宽），每一行都完整

v0.13.3（2026-09-20）

  • 本版没有功能改动，是「把已经发布的行为钉死」的一版。编译输出面板里 「双击一条诊断 → 编辑器跳到对应源码行」这个动作此前只有人工点验， 没有自动化把关；现在补上了端到端测试：用一套假工具链跑完 「执行编译 → 收输出 → 解析诊断 → 双击 → 定位」的完整链路，20 项断言全部通过
  • 修好一个早已失效的测试：查找结果列表的双击跳转用例此前发送的是 合成鼠标消息，在本机宿主上被控件直接忽略 —— 也就是说它一直是"绿"的， 实际却什么都没测。现在改用系统级真实输入，并加了前置断言 （结果列表为空时直接判失败，而不是静默通过）
  • 新增一道脚本编码守卫：脚本里写中文注释时，如果文件不带 UTF-8 BOM， PowerShell 5.1 会按系统 GB2312 代码页解码，可能吞掉一个换行， 从而报出一个与真实位置完全无关的「幽灵语法错误」。该守卫已挂进 CI， 并给 5 个受影响的脚本补上了 BOM

v0.13.2（2026-09-20）

  • 编译输出面板：两类此前"点不动"的诊断现在能正确定位。厂商编译器在检查 声明文件（.dec）时，报错格式与 .pat 完全不同 （<< File:[…] Line:[N] Last_Token:[…] >>），此前完全不认这种写法， 这类错误没有任何跳转目标；现在能认，并把位置正确挂到紧随其后的那条消息上
  • 链接阶段的报错不再跳到中间文件：编译器在链接时给的位置指向 .pdt 中间文件，此前点过去会打开一个中间产物；现在还原成真正的 .pat 源码 （行号沿用 —— .pdt 本来就是从 .pat 换扩展名生成的）
  • 其余解析行为不变：厂商编译器编译成功时也会打印的 Errors : 0   Warning : 0 统计行仍只作原文展示， 不计级别、不进计数

v0.13.1（2026-09-20）

  • 修掉编译输出面板的两个定位错误：编译器给的路径可以含空格 （例如 C:\Program Files (x86)\…\xlocale(337)），此前按"最后一个空白之后" 取文件名，会把路径截成半截 —— 而半截串照样"看着像路径"，所以不报错、只是静默指错。 现在从行首取。另外错误正文里也可能出现数字括号（如 (位于"…(623)")）， 此前会把位置认到正文里去、导致那一行点不动；现在只认「括号里是数字」 且「括号后紧跟冒号」的那个括号
  • 停报一条误报：此前依据厂商手册的明文说明，把 SPM_PATTERN(…, NORM, K_SET) 判成错误（C3380-PAT-002）。 真机实测发现编译器接受它（编译通过、产物逐字节相同）⇒ 属误报， 已按「宁可不报、不可误报」停报
  • 修一条端到端脚本的收尾缺陷：语言包脚本在清理阶段可能抛异常， 导致所有断言都通过、结论行也打印了、退出码却是 1

v0.13.0（2026-09-19）

  • CRAFT 编译集成（新增顶级「工具」菜单）：在编辑器里直接编译 Chroma 测试程序工程 —— 编译工程、编译输出面板（步骤 / 位置 / 级别 / 输出，与静态检查面板刻意分开）、 清除编译输出、指定 CRAFT 工具目录…。工具链自动探测 （设置 → CRAFT_HOME → PATH）；没装 CRAFT 时功能自动灰掉并说明原因， 不是弹错误框。编译在后台线程跑，失败即停，超时会把整棵子进程树一起结束 （编译器会自己再调 C++ 编译器，只杀父进程会留下孤儿占着文件句柄）。 输出里认不出位置的行走纯文本展示，不假装能跳转
  • 修掉「编译成功却挂一条警告」：厂商编译器在编译成功时也会打印一行 Errors : 0   Warning : 0 统计，此前被当成一条真实警告显示在 编译输出面板上（橙色的、看着像有问题）。现在先识别统计行、再判级别， 统计行保留原文但不计级别、不进计数；判据刻意从严，逐条诊断行不会被误吞
  • 修掉跨文件自动补全的时序竞态：打开 .pln 后立刻敲引脚名前缀时， 被引用 .dec 里的符号还没进词汇表 ⇒ 候选为空、不弹下拉（等半秒再看其实已经好了， 但补全早过去了）。现在换文档时同步刷新词源，不再等防抖； 并且关闭静态检查不再影响补全（此前关掉静态检查的人会完全失去跨文件补全， 而代码注释写的是「与开关无关」—— 注释是意图，行为才是用户拿到的东西）
  • 日 / 韩 / 繁中界面补齐：这三个语言文件此前各缺 18 个界面键 （诊断面板整块显示英文），现已与简中 / 英文完全对齐。新增两道自动守卫 （语言文件之间键集合 + 占位符一致、代码里引用的键必须存在），防止以后再漏
  • 器件定义（.dec）静态检查收窄：「引脚名重复」类规则改为 按引脚资源域判定（普通引脚 / UR / TMU 等各自独立成域， 域划分取自手册自己的默认引脚组）—— 在厂商真实工程语料上消掉 22 条误报， 且不影响正确路径
  • 另修：命令 ID 分配守卫（防止「区间撞单点」这类点 A 触发 B 的静默 bug）、 若干脚本里的硬编码盘符（换机器 / 虚拟机里跑不再起不来）

v0.12.0（2026-09-19）
